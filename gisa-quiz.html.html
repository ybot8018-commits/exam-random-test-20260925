① 소프트웨어 설계

🔗 결합도 (Coupling) — 모듈 사이의 의존도, 낮을수록 좋은 설계

시험 최다 출제 포인트. 약함(좋음) → 강함(나쁨) 순서를 그대로 암기.

자료(Data)→ 스탬프(Stamp)→ 제어(Control)→ 외부(External)→ 공통(Common)→ 내용(Content)
결합도설명
자료 결합도단순 값(자료)만 매개변수로 주고받음 — 가장 이상적
스탬프 결합도자료구조(배열, 객체) 형태로 통째로 전달
제어 결합도제어 신호(플래그, 스위치 등)를 넘겨 상대 모듈의 흐름을 제어
외부 결합도외부에 선언된 변수(전역변수)를 참조
공통 결합도동일한 전역 데이터 영역을 여러 모듈이 공유
내용 결합도한 모듈이 다른 모듈의 내부 로직/데이터를 직접 참조·수정 — 가장 나쁨
암기법: "자스제외공내" (자료-스탬프-제어-외부-공통-내용)

🧩 응집도 (Cohesion) — 모듈 내부 요소의 관련성, 높을수록 좋은 설계

기능적→ 순차적→ 교환(통신)적→ 절차적→ 시간적→ 논리적→ 우연적

왼쪽(기능적)이 가장 강함(좋음), 오른쪽(우연적)이 가장 약함(나쁨). 결합도와 정반대로 "좋은 것이 왼쪽"에 온다는 점에 주의.

좋은 설계 원칙 = 저결합(Low Coupling) · 고응집(High Cohesion)

나선형(Spiral)계획수립→위험분석→개발및검증→고객평가 반복, 위험관리 중심, 대규모 시스템 적합

③ 데이터베이스 구축

🗄️ 정규화 단계

단계조건 (제거 대상)
1NF모든 속성값이 원자값(더 이상 분해 불가)
2NF부분 함수 종속 제거 (기본키 전체에 완전 함수 종속)
3NF이행적 함수 종속 제거 (A→B→C 형태 제거)
BCNF결정자이면서 후보키가 아닌 것 제거
4NF다치 종속(Multi-valued Dependency) 제거
5NF조인 종속(Join Dependency) 제거
함수 종속 X→Y: X(결정자)의 값이 정해지면 Y(종속자)의 값이 유일하게 결정됨. 이행규칙: X→Y, Y→Z 이면 X→Z.

⚠️ 이상현상(Anomaly)과 정규화의 목적

삽입 이상 원치 않는 데이터까지 함께 삽입해야 함 삭제 이상 필요한 데이터까지 함께 삭제됨 갱신 이상 중복 데이터 중 일부만 수정되어 불일치 발생
정규화 목적: 데이터 중복 최소화, 이상현상 방지, 데이터 구조의 안정성 확보. (조회 성능 극대화는 반정규화의 목적)

📄 페이지 교체 알고리즘 & 스레싱

FIFO — 가장 먼저 적재된(오래된) 페이지 교체 LRU — 가장 오래 안 쓰인 페이지 교체 LFU — 사용 빈도 가장 낮은 페이지 교체 OPT — 이후 가장 늦게 쓰일 페이지 교체(이상적) NUR — 최근 사용하지 않은 페이지 교체(참조·수정 비트 활용)
스레싱(Thrashing): 페이지 교체(스와핑)에 걸리는 시간 > 실제 프로세스 수행 시간일 때 발생 → 성능 급락. 방지책: 각 프로세스에 충분한 프레임(워킹셋) 제공.
Best-Fit 요청보다 크면서 가장 작은 공간 배치(단편화 최소) Worst-Fit 가장 큰 공간에 배치 First-Fit 처음 발견한 맞는 공간에 배치

📐 LOC / COCOMO 비용산정

개발기간(월) = 총 라인수(LOC) ÷ (투입인원 × 1인당 월간 생산성)
예) 36,000라인 ÷ (6명 × 300라인) = 20개월
COCOMO 유형규모
Organic소규모, 단순 (5만 라인 이하) — 사무처리·과학기술 계산용
Semi-Detached중규모, 중간 복잡도 (30만 라인 이하)
Embedded대규모, 복잡·제약 많음 (내장형, 실시간)
LOC 기법 예측치 공식: (낙관치 + 4×기대치 + 비관치) / 6
